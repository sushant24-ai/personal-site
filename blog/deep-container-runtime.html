🎯 Deep into Container — Deep into Container Runtime

November 22, 2022 Containers Docker DevOps

Continuing from the previous post, we learned about the two main components of building containers — Linux Namespaces and Cgroups. In this post, we're going to explore container runtimes and understand their role in the container ecosystem.

Container runtimes are the software responsible for running containers. But here's what many people don't realize: there are actually two levels of container runtimes, each with different responsibilities.

📌 Low-Level Container Runtime

The low-level container runtime is the component closest to the operating system. Its primary job is to:

  • Create and configure namespaces
  • Set up cgroups
  • Actually start and stop container processes

The most common low-level runtime is runc, which is the reference implementation of the OCI (Open Container Initiative) runtime specification.

📌 High-Level Container Runtime

While the low-level container runtime focuses on creating and deleting containers, the high-level container runtime handles the bigger picture:

  • Downloading container images from registries
  • Managing container images locally
  • Running containers from images
  • Managing the lifecycle of multiple containers
  • Loading and unpacking container images for the low-level runtime

Containerd is the most common high-level container runtime. It provides features like:

  • Pulling images from container registries (Docker Hub, GCR, etc.)
  • Image management and storage
  • Container execution via low-level runtimes
  • Container supervision and management
flowchart TB subgraph HighLevel["High-Level Runtime (containerd)"] PULL[Pull Images] STORE[Store/Manage Images] UNPACK[Unpack Images] end subgraph LowLevel["Low-Level Runtime (runc)"] CREATE[Create Container] RUN[Run Process] end PULL --> STORE --> UNPACK --> CREATE --> RUN style PULL fill:#8b5cf6,color:#fff style STORE fill:#8b5cf6,color:#fff style UNPACK fill:#8b5cf6,color:#fff style CREATE fill:#3b82f6,color:#fff style RUN fill:#10b981,color:#fff
Note: Although containerd can run containers, it doesn't help you build container images and doesn't provide a user-friendly interface. That's where tools like Docker come in.

📌 Docker

Docker was one of the first tools to provide a complete container experience. It adds a user-friendly layer on top of the container runtime ecosystem:

  • Image build — Dockerfile and docker build
  • Image management — docker images, docker pull
  • Container management — docker run, docker ps, docker rm
  • Image sharing — docker push
  • User interface — Docker Desktop, CLI

Under the hood, Docker uses its own components that map to the runtime hierarchy:

  • dockerd — The Docker daemon that provides the API and build features
  • docker-containerd — Similar to containerd, manages images and containers
  • docker-runc — Similar to runc, actually creates and runs containers

📌 Conclusion

Understanding container runtimes helps you appreciate what's happening behind the scenes when you run docker run. Let's summarize:

  • Low-level runtimes (like runc) are responsible for creating and deleting containers
  • High-level runtimes (like containerd) manage container images and container lifecycle
  • Docker is a complete tool that wraps these runtimes with build capabilities and a user-friendly interface
